# Building veltra.exe on Windows

`veltra.exe` is the Windows desktop app: a native Win32 window that shows the Veltra UI in Microsoft Edge WebView2,
with the engine and HTTP server running in the same process (127.0.0.1, random port, per-session token).
`veltra.exe --headless [server options]` runs only the server, exactly like `veltra-server` on Linux.

The result is one self-contained file: UI embedded, static C/C++ runtime, no `WebView2Loader.dll` (Veltra finds the
installed WebView2 Evergreen runtime itself). Users need the WebView2 Runtime, which ships with Windows 11 and current
Windows 10 builds; without it, Veltra explains how to install it and opens the UI in the default browser instead.

## Compiler: MinGW-w64 (GCC) or clang, not MSVC

The CPU kernels use GCC/clang-only features (`__attribute__((target(...)))` per-function ISA dispatch, vector
extensions). **MSVC (cl.exe) cannot compile the engine.** Use MinGW-w64 (GCC 13 or newer, posix threads), for example
WinLibs or MSYS2. clang-cl / Visual Studio's clang has not been tested.

## Three commands (native Windows build)

```bat
:: 1. MinGW-w64 toolchain (WinLibs GCC, posix threads) + CMake. Open a new terminal afterwards so PATH is updated.
::    MSYS2 alternative: pacman -S mingw-w64-ucrt-x86_64-gcc mingw-w64-ucrt-x86_64-cmake  (use the UCRT64 shell)
winget install --id BrechtSanders.WinLibs.POSIX.UCRT -e && winget install --id Kitware.CMake -e

:: 2. configure (from the repo root: the folder with CMakeLists.txt)
cmake -B build -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release

:: 3. build the desktop app -> build\veltra.exe
cmake --build build --target veltra -j
```

Put models (`*.vlt`) in a `models` folder next to `veltra.exe`, or pick a file from the app.

## Cross-compiling on Linux (what we use for releases)

```bash
sudo apt-get install g++-mingw-w64-x86-64-posix cmake   # provides x86_64-w64-mingw32-g++-posix + windres
bash tests/build_win_mingw.sh . build-win                 # -> build-win/veltra.exe
```

The script prints the DLL imports at the end; they must be Windows system DLLs only (KERNEL32, USER32, GDI32,
ADVAPI32, SHELL32, ole32, dwmapi, bcrypt, WS2_32, WININET, msvcrt) - no libstdc++, libgcc, libwinpthread or
WebView2Loader.dll.

## Useful switches

| | |
|---|---|
| `veltra.exe --headless --port 8099` | server only (console output); add `--open-browser` to open the hub page |
| `veltra.exe --model C:\models\x.vlt` | desktop app with a model loaded at start; any `veltra-server` option works |
| `VELTRA_LOG_FILE=C:\temp\veltra.log` | append the server log (stdout + stderr) to a file, also in window mode |
| `VELTRA_DEVTOOLS=1` | enable the WebView2 dev tools (F12) |
| `VELTRA_DATA_DIR=...` | data folder instead of `%APPDATA%\Veltra` (chats, WebView2 profile in `WebView2\`) |

The app icon is generated by `python scripts/make_veltra_icon.py` (standard library only) into `engine/win/veltra.ico`.
